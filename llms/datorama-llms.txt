# Datorama (Salesforce Marketing Cloud Intelligence)

> Datorama is a marketing intelligence and analytics platform that unifies marketing, advertising
> and sales data from thousands of sources into one AI-assisted reporting layer. Salesforce
> acquired Datorama in August 2018 and rebranded it Marketing Cloud Intelligence. The developer
> portal, the API hosts and the @datorama package scope are all still live under the datorama.com
> domain; the marketing, pricing, legal, trust and support surfaces have moved to salesforce.com.

This file was generated by API Evangelist from the provider's own public developer portal and
package registries on 2026-08-12. Datorama does not publish an llms.txt (probed:
https://developers.datorama.com/llms.txt -> 404).

## APIs

- [Intelligence Platform API](https://developers.datorama.com/docs/manage/introduction/): REST API
  to set up, manage and administer an Intelligence account — workspaces, accounts, users,
  permission sets, data streams, connectors, dimensions, measurements, dashboards, pages, reports,
  report jobs and schedulers. Base: `https://api.datorama.com/v1`
- [Intelligence Query API](https://developers.datorama.com/docs/query/introduction/): synchronous
  JSON query API for reading harmonized Intelligence data out to any other platform. 60-second
  timeout, up to ~600,000 rows. `POST /v1/query`, `POST /v1/query-batch`
- [Reporting API](https://developers.datorama.com/docs/query/query-vs-reporting-api/): asynchronous
  sibling of the Query API for large exports — 40-minute timeout, up to ~5,000,000 rows, polled by
  report-job id and delivered to email/FTP/S3/Dropbox/Google Drive
- [MCI MCP server](https://www.npmjs.com/package/@datorama/mci-mcp-sdk): first-party local stdio
  MCP server (published 2026-07-21) that proxies MCP JSON-RPC to a tenant `/api/mcp` endpoint with
  an OAuth2 service-account bearer

## Authentication

- All Platform and Query API requests carry a personal API access token in the `Authorization`
  header (no `Bearer` prefix in the documented example)
- [Generating an API token](https://help.salesforce.com/s/articleView?id=sf.dato_getstarted_token_api.htm&type=5)
- API access is a paid feature and requires user-level activation by the account manager

## Runtime semantics

- Rate limits: 60 Platform API req/min, 200 Query API req/min, 20,000 calls/day (UTC), all per USER
  not per account. Headers: `X-PlatformRateLimit-*`, `X-QueryRateLimit-*`, `X-DailyQuota-*`.
  Exhaustion returns `429 Too Many Requests`
- Sandbox: send `sandbox-mode: true` to run a call against the Intelligence sandbox
- Updates: `PATCH` is the recommended partial update; a `PUT` that omits fields CLEARS them
- Entity history fields (`createUserId`, `createUser`, `createTime`, `updateUserId`, `updateUser`,
  `updateTime`) are server-managed and ignored on write
- Query API errors: `422` for query-parse failures; runtime errors come back inside a `200` with a
  non-empty `errors` property
